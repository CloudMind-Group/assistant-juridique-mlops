Tout ce qu'il faut savoir pour contribuer sans casser le projet : la structure, les branches, le cycle d'une pull request et la livraison hebdomadaire. Cinq minutes de lecture, à faire une fois.

3 Ta journée type

  1. Pars toujours d'un develop à jour 
    git checkout develop
git pull
  2. Crée ta branche, préfixée par ton module 
    git checkout -b feature/m2-reranking

    m1…m8 : ça rattache ta branche à ton module et à ton pilote.

  3. Travaille et commite en petit 
    git add -A
git commit -m "feat(m2): ajoute le re-ranking par cross-encoder"

    Format : type(module): description à l'infinitif.
    Types : feat · fix · docs · refactor · test · chore

  4. Pousse et ouvre la pull request vers develop 
    git push -u origin feature/m2-reranking
gh pr create --base develop

    Ou depuis GitHub : le bouton « Compare & pull request » apparaît tout seul. Remplis le gabarit, il ne prend pas deux minutes.

  5. Attends le feu vert, puis fusionne en squash

    Deux conditions : la CI verte et une approbation de l'équipe propriétaire du fichier. Ensuite, bouton Squash and merge, puis supprime la branche.

Tu ne peux pas approuver ta propre PR. C'est voulu : le principe des quatre yeux. Si tu es bloqué, ping le pilote concerné — il a 24 h pour relire.

5 La livraison du vendredi

Chaque fin de semaine = une version. C'est l'équipe platform qui la pilote, mais tout le monde doit comprendre le principe.

# 1. on gèle ce qui est dans develop
git checkout develop && git pull
git checkout -b release/0.2.0
git push -u origin release/0.2.0

# 2. plus AUCUNE nouveauté ici — uniquement des corrections de test

# 3. on livre dans main, puis on pose l'étiquette
gh pr create --base main --title "release: 0.2.0"
git checkout main && git pull
git tag -a v0.2.0 -m "Semaine 2 — RAG & API v1"
git push origin v0.2.0

# 4. on RAMÈNE les corrections dans develop
gh pr create --base develop --head release/0.2.0
L'étape 4 est celle qu'on oublie. Les corrections faites pendant le gel n'existent que dans release et main. Sans ce retour, la semaine suivante repart d'un develop qui contient encore le bug.
