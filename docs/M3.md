# M3 — Experiment Tracking & Model Registry

## Objectif

Le module M3 assure la traçabilité des expérimentations RAG,
l'évaluation des performances et la gouvernance des versions de modèle.

## Composants

### MLflow Tracking

`src/m3_tracking/mlflow_tracker.py`

Enregistre :

- paramètres des expériences ;
- métriques ;
- latences ;
- nombre de citations ;
- statut de refus des réponses.

### Model Registry

`src/m3_tracking/model_registry.py`

Gère :

- l'enregistrement des versions candidates ;
- l'alias `candidate` ;
- la promotion vers `champion` ;
- les règles minimales de qualité.

### RAGAS Evaluation

`src/m3_tracking/ragas_evaluator.py`

Prépare les données d'évaluation :

- question ;
- réponse ;
- contextes récupérés ;
- réponse de référence lorsqu'elle est disponible.

### Evaluation Runner

`src/m3_tracking/evaluation_runner.py`

Relie l'évaluation des réponses au système de tracking MLflow.

### Regression Detection

`src/m3_tracking/regression.py`

Compare une version candidate avec une baseline et détecte les
dégradations importantes de métriques.

### Model Card

`src/m3_tracking/model_card.py`

Produit une Model Card contenant :

- version ;
- description ;
- métriques ;
- limitations ;
- date de génération.

### Quality Gate

`src/m3_tracking/quality_gate.py`

Bloque une promotion lorsqu'une métrique obligatoire est absente,
sous le seuil attendu ou en régression significative.

## Installation

Installer les dépendances du projet et de M3 dans l'environnement virtuel :

```bash
python -m pip install -r requirements.txt
python -m pip install mlflow ragas
```

## Vérification locale

### 1. Préparer le corpus M1

Si les données ne sont pas déjà disponibles localement :

```bash
python -m src.m1_ingestion.dataset_generator --count 60
python -m src.m1_ingestion.ingest --raw-dir data/raw --out-dir data/processed
```

Les données générées dans `data/raw` et `data/processed` restent locales
et sont exclues de Git.

### 2. Vérifier le corpus avec M2

```bash
python -m src.m2_rag.cli validate-corpus
```

Exemple de résultat :

```text
{"documents": 60, "status": "valid"}
```

### 3. Vérifier le pipeline RAG M2

```bash
python -m src.m2_rag.cli smoke-light
```

Le test doit produire une réponse non refusée avec des chunks récupérés
et au moins une citation.

Le backend Qdrant local peut également être vérifié avec :

```bash
python -m src.m2_rag.cli smoke-qdrant-local
```

### 4. Lancer MLflow

Dans un premier terminal :

```bash
mlflow server --host 127.0.0.1 --port 5000
```

L'interface MLflow est alors disponible à l'adresse :

`http://127.0.0.1:5000`

### 5. Tester l'intégration M1 → M2 → M3 → MLflow

Dans un deuxième terminal, depuis la racine du dépôt :

```bash
python -m scripts.m3_real_integration
```

Ce test exécute le flux :

```text
Corpus M1
   ↓
Pipeline RAG M2
   ↓
RAGResponse
   ↓
MLflowTrackingHook M3
   ↓
MLflow
```

Un run nommé :

```text
m1-m2-m3-real-corpus
```

doit apparaître dans MLflow.

Le run contient notamment :

- `prompt_version` ;
- `model_version` ;
- `retrieval_ms` ;
- `generation_ms` ;
- `total_ms` ;
- `retrieved_chunks` ;
- `citation_count` ;
- `refused`.

### 6. Tester le pipeline d'évaluation M3

```bash
python -m scripts.m3_ragas_integration
```

Un run nommé :

```text
m2-m3-evaluation-dev
```

doit apparaître dans MLflow.

Ce test valide l'intégration technique entre :

```text
M2 RAG
   ↓
RAGASEvaluationSample
   ↓
EvaluationRunner
   ↓
MLflow
```

Les métriques `dev_*` utilisées par ce smoke test sont des métriques
techniques de validation du pipeline. Elles ne constituent pas un
benchmark RAGAS de production ni une évaluation avec ground truth annotée.


Pour exécuter l'ensemble de la suite de tests du projet :

```bash
python -m pytest -q
```

## Notes

- `mlflow.db` est une base locale et ne doit pas être versionnée.
- Les données présentes dans `data/raw` et `data/processed` ne doivent pas
  être ajoutées au dépôt Git.
- Les scripts d'intégration sont destinés à permettre aux membres de
  l'équipe et aux reviewers de reproduire localement la validation M3.
- Les métriques RAGAS nécessitant une référence annotée ou un LLM juge
  doivent être distinguées des métriques techniques utilisées pour les
  smoke tests locaux.
